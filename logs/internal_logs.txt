v3.1.1 

1. n.field.free() fails on struct fields
   - string field: TypeError "field 'free' is not callable"
   - list field: MemoryError "free() can only be called on an owning variable"
   - Make it work, or at least give the same error for both.
   - Workaround: string t = n.name, then t.free()

2. Assigning to a string field leaks the old value
   - Free the old pointer before the store.

3. Assigning to a list field leaks the old value
   - Free the old pointer with the list free fn before the store.

4. List<string>.free() calls _zen_string_free instead of _zen_list_free
   - List<int> is correct.
   - Pick the free fn by the outer type (List) first.

5. Check: does _zen_list_free free the string elements of a List<string>

6. Note: free() only works on a named variable
   - make(i).free() gives MemoryError "free() can only be called on an owning variable".
   - To free a returned value, assign it first: List<int> a = make(i), then a.free().
   - Discarding a returned value (make(i);) leaks. That is expected in manual-free Zen.
   - Consider documenting this, or a compiler warning for an unused owning return value.
7. update docs about the owenerships and potential UB.
