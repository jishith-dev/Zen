Zen v3.0.0 - Internal Changelog Note

BREAKING
  - Renamed toString/toInt -> asciiToInt/intToAscii for ASCII conversion.
  - JSON integers decoded via .map() are now Long, not Int.
    -> use getLong() for all JSON integer values post-map.
  - "private" is now a reserved keyword (functions, methods, fields).
    -> collides with any existing identifier named "private".

LANGUAGE / TYPE SYSTEM
  - Formalized numeric widening: byte -> int -> long -> double.
  - bool participates in arithmetic (true=1, false=0) and bitwise ops.
  - New bitwise operators: & | >> << ~
  - Unary + added.
  - infer supports: int, bool, double, string, long, byte
    (errors on list/struct/other).
  - Compile-time constants supported (e.g. int N = 10; int arr[N]).
  - sizeOf() supports bare types and expressions; bare struct names
    still unsupported (must instantiate first).
  - Struct field initializers with defaults; uninitialized structs get
    zero-value fields (0, "", false, empty list, etc).
    Struct literals only set the fields explicitly given.
  - Anonymous/inline functions as callback args; compiled as separate
    functions, no closures (no variable capture).

STDLIB / RUNTIME
  - HttpRequest.getHeader added.
  - extName() (no dot) vs path.extname() (with dot) - naming clarified.
  - length() now accepts List directly, alongside list.length.
  - List methods added: remove(), reverse(), sort(), sum(), avg().
  - Map methods added: keys(), entries().
  - stringToBytes / bytesToString globals added.
  - TCP networking built in:
      structs: Tcp, TcpServer
      net.online(), net.connect(host, port), net.listen(port)
      Tcp: send(), receive(), close(), isOpen()
      TcpServer: accept(), close(), isOpen()
      (native impl: tcp.c)
  - Real concurrency: thread fn now accepts parameters, catches
    compile-time capture errors.
    threads.count(), threads.currentId() added.

PACKAGES / CLI
  - zen install / uninstall accept multiple package names at once.
  - zen installed (lists installed package count).
  - zen deps auto-detects/records native/*.o; native objects auto-link.
  - .c files supported as native dependencies.
  - zen.json flags: [] supported at module + standalone level
    (e.g. --flags -lmariadb).
  - zen read pkgname [--raw] renders package README in terminal.
  - zen update --dev installs dev version.
  - zen upgrade pkgName; zen install pkg@semver support.
  - --link a.o b.o supported.
  - Multiple exports/imports per file supported.
  - Import aliasing for functions/variables (not yet for structs).
  - zen tests, zen info (namespace/global, with --methodName) added.
  - Interactive REPL (zen with no args), prints "Bye!" on exit().
  - Better compile-time diagnostics: hints + source text.

INSTALLER (install.sh)
  - --tag / --branch install modes; branch installs skip VERSION
    check and version off short commit hash.
  - Verified end-to-end on Termux (Android) and reviewed for
    apt/pacman/dnf/zypper Linux paths; Windows unsupported for now
    (documented, not auto-installed).

  - added new global built-in -- lastIndexOf
  - removed keyword 'in'
  - enforce classic loop always loop (init, cond, update)

Json.map() should pick getInt()/getLong()/getByte() based on usage, with overflow checks for each (int overflow check, byte overflow check, etc.) — not just default to one rule for all numeric values.
Byte is signed (-128 to 127) — document this explicitly.
Scientific notation (1e300, 1.5e-10) is now supported in numeric literals.

Hex literals with no suffix are always int — even if the hex digits happen to end in a letter like B or F (e.g. 0xFB is int 251, not a byte).
Hex + type suffix requires an underscore before the suffix letter, since B is a valid hex digit and ambiguous otherwise: 0xFB_B → byte, 0xFF_L → long. No underscore = no suffix, always int.
Decimal literal suffixes (20B, 42L) are unaffected — no ambiguity there, unchanged behavior.
Scientific notation (1e300, 1.5e-10, 2E+5) now supported for double literals, both in source parsing and in formatDouble's LLVM-output formatting (fixes invalid 1e-9-style constants that lack a required decimal point).
Byte is signed, -128 to 127; hex/decimal values outside that range wrap via two's complement when suffixed as byte.

Added \e and \xHH string escapes (via a new readEscape() in the lexer), plus ESC handling in toLLVMString, so ANSI escape codes like "\e[31m" work in Zen strings.

added new http namespace method http.getProgress(url, callback) void return, params - percentage (int) - pending
it return list of bytes for low level controlling

HTTP timeout behaviour (curlRuntime.c, zen_request)

- Connect timeout: 10 s for every request. Fails if the server can't be reached.
- Requests WITHOUT a progress callback (get/post/put/patch/delete):
  hard total cap of 30 s.
- Requests WITH a progress callback (getProgress, i.e. downloads):
  no total cap. Aborts only if speed stays below 1 KB/s for 30 s
  (CURLOPT_LOW_SPEED_LIMIT / LOW_SPEED_TIME), so large, slow downloads
  finish and dead connections fail fast.
- On any curl error (including timeout or "Operation too slow"),
  http_error() prints a NetworkError and exits the program.
- Tested: 3.4 MB PDF (gcc.pdf) downloads correctly with the new settings.

Not implemented yet: user-configurable timeouts, retry/resume.
